# BRANDIRASCK Influencers — Netlify / PostgreSQL

Standalone Influencers platform with one central Netlify API + PostgreSQL and separate static Admin/Public frontends.

## Layout

- `admin/` — Admin frontend
- `public/` — Influencer frontend
- `netlify/functions/api.js` — central API function
- `netlify/functions/cleanup.js` — scheduled cleanup
- `api/` — server logic
- `sql/schema.sql` — PostgreSQL schema
- `scripts/hash-password.mjs` — secure Admin password hash generator

## Important deployment model

The current package is prepared for:

- Admin/API: `https://brandirascK-admin.netlify.app`
- Public: `https://beautiful-croquembouche-528a2e.netlify.app`

Both frontends use the Admin site's `/api` endpoint as the central API. If you change either domain, edit only `admin/api-config.js` and `public/api-config.js`.

## Environment variables — central API site

Set these in the Netlify site that deploys the repository root:

- `DATABASE_URL` — PostgreSQL connection string
- `ADMIN_USERNAME` — Admin username
- `ADMIN_PASSWORD_HASH` — scrypt hash generated by `npm run hash-password`
- `SESSION_SECRET` — long random secret
- `ALLOWED_ORIGINS` — optional comma-separated Admin/Public origins

Do not commit secrets. Do not use `ADMIN_PASSWORD` in production.

## Database

Run `sql/schema.sql` once against the PostgreSQL database.

## Generate Admin password hash

Run:

```bash
npm install
npm run hash-password
```

Copy the generated `scrypt$...` value into `ADMIN_PASSWORD_HASH`.

## Health check

Open the central API endpoint:

`https://brandirascK-admin.netlify.app/api?action=health`

Expected response includes `ok: true`.

## Workflow

Admin login → Generate Code → Public Code validation → Registration → Review → Contract acceptance → temporary PDF → Admin approval → Active Catalog.

## Security changes in this package

- Admin passwords use Node.js `scrypt`, not plaintext/SHA-256.
- Admin session tokens are stored as HMAC-SHA256 hashes using `SESSION_SECRET`.
- Browser origin allow-list is supported through `ALLOWED_ORIGINS`.
- Server-side code expiry and one-time use remain enforced.
- Temporary PDFs remain time-limited and are cleaned by the scheduled function.
